Boltz design reference

Boltz is the colour scheme and design language for every tool in these dotfiles, inspired by teenage engineering. It reads like the faceplate of a piece of music hardware: near-monochrome greys, one orange accent, and colour that only appears when it means something.

01Principles

  1. Greys carry the structure. Surfaces, rules and text sit on one warm, near-neutral grey ramp. Nothing gets a hue unless the hue carries meaning.
  2. One accent. Orange marks the active thing: the cursor, the current turn, links, keywords, a running step, a numbered list. There is never a second accent.
  3. Colour is a category. Blue reads, green writes, orange runs, ink delegates, red fails. The mapping is the same in every port, so a colour means the same thing in the terminal, the editor and a report.
  4. Rules, not shadows. 1px lines in line, frame and rule separate things. No drop shadows, no gradients, radii of 6px or less.
  5. Labels are hardware labels. Mono, uppercase, letter-spaced 0.1 to 0.16em, in grey. The value sits next to or under the label in ink, bold. Knobs are ◉, categories are ■.
  6. Real numbers, tabular figures. Durations, counts and percents are exact and aligned: 0.21s, 34%, 02. Turn numbers are zero-padded to two digits.
  7. Gear vocabulary is decoration. Status words borrow from music gear: work is sequencing, sampling, bouncing, mixing, patching, tracking, tuning or looping. Anything you refer to by name keeps its plain name: a prompt and its reply are a turn, as in Claude Code and the status line.
  8. Both modes, always. Every port ships dark and light. toggle-theme.sh flips the terminals, editors and Claude Code together; Obsidian and reports follow the system appearance.

02Palette

Canonical tokens. Ports take their values from this table. A _text token is the same hue tuned to read as text on bg; the plain token is for marks, glyphs and fills.

TokenRoleDarkLight

Terminal ANSI 16

Boltz has no yellow, magenta or cyan of its own. Yellow takes the orange accent; magenta and cyan are muted blends so they stay quiet. Bright variants are a small step up, not neon. In light mode slot 0 is ink and slots 7 and 15 are dark greys, so programs that print "black" or "white" text stay readable.

03Categories

Every tool call, diff and status maps to one of five categories. Red is not a category: it only marks failure.

Delegates
Agent, Task, Skill

Everything else
MCP tools and the rest

The same hues carry into the editors: additions and success are green, deletions and errors are red, warnings and modified lines are orange, information and links are blue.

05Syntax

Editors (Neovim, VS Code) colour code by role. Prose and identifiers stay ink, so colour stays meaningful.

Keyword · orange_text Type · blue_text Function · teal String · green_text Number, constant · violet Comment, operator · grey
Gopool.go
package proxy

// healthyBackends returns the backends that answered their last check.
func (p *Pool) healthyBackends(now time.Time) []*Backend {
	healthy := make([]*Backend, 0, len(p.backends))
	for _, b := range p.backends {
		if now.Sub(b.LastSeen) > p.idleTimeout {
			continue // stale, skip it
		}
		healthy = append(healthy, b)
	}
	if len(healthy) == 0 {
		p.log.Warn("no healthy backend", "pool", p.name, "retry", true)
	}
	return healthy
}

Reports use a reduced set: keyword orange, function blue, string green, comment grey.

06Terminal

Claude Code with the boltz mod, the Claude Code theme and the status line. Notes in grey name the render site that draws each element. Notes in orange are proposed and not built yet.

Adding a port

  • Take every value from the palette table. If a tool needs a colour the table lacks, derive it from an existing token (a mix toward bg) instead of inventing a hue.
  • Keep the category mapping and the single accent.
  • Ship dark and light, and teach toggle-theme.sh to switch it.
